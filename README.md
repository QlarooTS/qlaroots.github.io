# Zaltett2 — сайт для GitHub Pages

Готовый статический сайт для команды **QlarooTS**: тёмный минималистичный лендинг, кнопка скачивания расширения **Zaltett2**, описание, инструкция по установке и FAQ.

## Что лежит в папке

```
zaltett2-site/
├── index.html                  # вся структура страницы
├── assets/
│   ├── styles.css              # дизайн, адаптив, анимации
│   ├── script.js               # кнопки скачивания, анимации, FAQ, уведомления
│   ├── config.js               # ← единственное место, где меняется ссылка на скачивание
│   └── favicon.svg
├── downloads/
│   └── Zaltett2.zip            # готовый архив расширения (скачивается кнопками)
├── extension-source/           # оригинальные 4 файла с твоего Google Drive (для справки)
└── README.md                   # эта инструкция
```

### Важное про ZIP

В папке на Google Drive лежали не архив, а четыре отдельных файла: `manifest.json`, `popup.html`, `background.js`, `icon.png`. Я собрал из них `downloads/Zaltett2.zip`.

В **собранном ZIP** сделаны только косметические правки:
- в `manifest.json` имя изменено на `Zaltett2 — QlarooTS` и обновлено описание;
- в `popup.html` заголовок и подпись переведены на брендинг QlarooTS, а в поле адреса по умолчанию вставлен рабочий сервер команды.

Оригинальные файлы как есть сохранены в `extension-source/`. Если хочешь распространять версию без правок — просто замени `downloads/Zaltett2.zip` своим архивом, сайт менять не нужно.

> Расширение — это клиент: оно сохраняет адрес сервера и открывает текущую вкладку через endpoint `/fetch?url=...`. Сам Zapret работает на сервере команды.

### Сервер по умолчанию

`https://8000-isx0bdbob8dt55f541oxm.e2b.app`

Этот адрес прописан в popup расширения и выведен на сайте в блоке «Сервер по умолчанию», в разделе «Установка» и в FAQ. Он задаётся одной переменной `defaultServerUrl` в `assets/config.js` — поменял там, обновил все упоминания на странице. Если сервер в `@e2b.app` перестанет отвечать (такие превью могут засыпать), просто укажи новый адрес в `config.js` и в `downloads/Zaltett2.zip`.

## Пошагово: как запустить сайт

### Шаг 1. Посмотреть сайт локально (необязательно, но полезно)

Открой терминал в папке `zaltett2-site` и запусти:

```bash
cd zaltett2-site
python3 -m http.server 8000
```

Затем открой `http://localhost:8000` в браузере. Проверь кнопки скачивания и мобильный вид. Чтобы остановить сервер — `Ctrl+C`.

### Шаг 2. Создай репозиторий на GitHub

1. Зайди на https://github.com/new.
2. В поле **Repository name** введи строго: `твойлогин.github.io` (например, `qlaroots.github.io`).
   - Именно такое имя нужно, чтобы сайт открывался по адресу `https://твойлогин.github.io`.
   - Для организации адрес будет `https://организация.github.io` — репозиторий тогда создаётся в ней.
3. Выбери **Public**.
4. **Не ставь** галочки `Initialize this repository with a README`, `.gitignore`, `license` — пустой репозиторий проще.
5. Нажми **Create repository**.

### Шаг 3. Загрузи файлы

Самый простой способ — через веб-интерфейс:

1. На странице нового репозитория нажми **uploading an existing file**.
2. Перетащи **всё содержимое** папки `zaltett2-site` (не саму папку, а `index.html`, папки `assets`, `downloads`, `extension-source` и `README.md`).
3. Внизу напиши коммит, например `Add Zaltett2 landing page`, и нажми **Commit changes**.

Или через терминал:

```bash
cd zaltett2-site
git init
git add .
git commit -m "Add Zaltett2 landing page"
git branch -M main
git remote add origin https://github.com/ТВОЙ_ЛОГИН/твойлогин.github.io.git
git push -u origin main
```

### Шаг 4. Включи GitHub Pages

1. Открой репозиторий → **Settings** → слева **Pages**.
2. В блоке **Build and deployment** → **Source** выбери `Deploy from a branch`.
3. **Branch** → `main`, папка → `/ (root)`. Нажми **Save**.
4. Через 1–3 минуты обнови `https://твойлогин.github.io`. Готово.

Если страница не открылась: проверь вкладку **Actions** в репозитории — там видно ошибку сборки. Чаще всего проблема в неправильном имени репозитория.

### Шаг 5. Что потом поменять

**Ссылка на скачивание** — `assets/config.js`, строка `downloadUrl`.

По умолчанию:

```js
downloadUrl: "./downloads/Zaltett2.zip",
```

Это работает сразу: ZIP лежит в репозитории и отдаётся GitHub Pages.

Если хочешь раздавать архив через Google Drive:

1. Загрузи `Zaltett2.zip` на Drive.
2. ПКМ по файлу → «Получить ссылку» → доступ «Все, у кого есть ссылка».
3. Скопируй `id` из ссылки вида `drive.google.com/file/d/ID_ФАЙЛА/view`.
4. В `assets/config.js` поставь прямую ссылку на файл:

```js
downloadUrl: "https://drive.usercontent.google.com/download?id=ID_ФАЙЛА&export=download&confirm=t",
```

Ссылку именно **на папку** (`/drive/folders/...`) вставлять нельзя: браузер откроет папку, а не начнёт скачивание. Сайт такой момент ловит и показывает подсказку.

**Адрес в макете на главной** — там же, `serverDisplay`. Это просто текст для дизайна, реально никуда не отправляется.

**Сервер по умолчанию во всех текстах** — `defaultServerUrl` в том же файле. Скрипт сам подставляет его во все места на странице.

**Тексты, цвета, карточки** — `index.html` и `assets/styles.css`. Акцентный цвет задаётся одной переменной `--accent` в начале CSS-файла.

### Шаг 6. Обновление расширения

1. Положи новый архив в `downloads/Zaltett2.zip` (имя оставь тем же).
2. Закоммить и запушь: `git add . && git commit -m "Update Zaltett2 build" && git push`.
3. GitHub Pages обновит сайт автоматически за минуту. Если браузер отдаёт старую версию — сделай жёсткую перезагрузку (`Ctrl+Shift+R`).

## Как обновить сайт с компьютера (если загружал через веб)

GitHub не даёт удобно править бинарный ZIP через веб-интерфейс, поэтому для обновления архива удобнее один раз настроить Git:

```bash
git clone https://github.com/ТВОЙ_ЛОГИН/твойлогин.github.io.git
cd твойлогин.github.io
# положи новый файл в downloads/
git add .
git commit -m "Update extension"
git push
```

## Частые вопросы

**Репозиторий приватный, и Pages не включается.** На бесплатном тарифе GitHub Pages работает только с публичными репозиториями. Открой Settings → General → Danger Zone → Change visibility → Public. ZIP и сайт не содержат секретов, так что это безопасно.

**Кнопка ничего не скачивает.** Проверь `assets/config.js`: ссылка должна вести к файлу, а не к папке Drive. Открой консоль браузера — там будет предупреждение.

**Сайт открывается, но стили «плоские».** Проверь, что папка `assets` загружена целиком и лежит рядом с `index.html`.

**Хочу свой домен.** Settings → Pages → Custom domain, впиши домен и добавь CNAME у регистратора. В репозитории появится файл `CNAME`; удалять его не надо.

**Нужен HTTPS.** GitHub Pages включает его автоматически для `*.github.io` и для подключённого домена (галочка Enforce HTTPS).

## Небольшое предупреждение

Расширение открывает страницы через сервер команды по умолчанию (`https://8000-isx0bdbob8dt55f541oxm.e2b.app`): владелец этого сервера технически видит запросы. Не указывайте в настройках сторонние неизвестные адреса.
